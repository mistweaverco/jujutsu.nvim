1. INTRODUCTION                                                 *jujutsu-intro*

jujutsu.nvim provides a Magit-inspired UI for the Jujutsu (jj) VCS.

No user commands are registered. Use the Lua API (see |jujutsu-api|).

==============================================================================
2. REQUIREMENTS                                         *jujutsu-requirements*

- Neovim 0.10+
- `jj` on PATH

Optional (pick at most one per category):

Diff:  diffview.nvim  or  codediff.nvim
Pick:  telescope.nvim | fzf-lua | mini.pick | snacks.nvim

Forge review (see |jujutsu-review|):
  GitHub: `gh`  |  GitLab: `glab`  |  Forgejo/Codeberg & Bitbucket: `curl` + tokens

Without a picker plugin, a built-in fuzzy finder is used.

3. SETUP                                                         *jujutsu-setup*

>
  require("jujutsu").setup({
    kind = "tab",
    use_default_keymaps = true,
    disable_signs = false,
    signs = {
      add = { text = "┃" },
      change = { text = "┃" },
      delete = { text = "▁" },
      topdelete = { text = "▔" },
      changedelete = { text = "~" },
    },
    annotate = { panel_height = 16 },
    file_history = { limit = 200, panel_height = 16 },
    mappings = {
      status = { ["q"] = "Close" },
      popup = { ["c"] = "ChangePopup" },
    },
    integrations = {
      telescope = nil,  -- nil = auto, true/false = force
      fzf_lua = nil,
      mini_pick = nil,
      snacks = nil,
      diffview = nil,
      codediff = nil,
    },
    diff_viewer = nil,  -- "diffview" | "codediff" | nil
    forge = {
      pr_integration = true,
      review = { enabled = true },
      bitbucket = { user = nil, token = nil },
      forgejo = { token = nil },
      hosts = {},
    },
  })
<

Example lazy.nvim keys (no `cmd`):
>
  keys = {
    { "<leader>gg", function() require("jujutsu").open() end },
    { "<leader>jb", function() require("jujutsu").annotate() end },
    { "<leader>jr", function() require("jujutsu").review() end },
  }
<

==============================================================================
4. API                                                             *jujutsu-api*

                                                            *jujutsu.open()*
open({opts})              Open the status buffer, or a popup if opts[1] is set.

  Options: ~
    cwd    string   repository directory
    kind   string   tab|split|vsplit|floating|replace|auto|...
    [1]    string   popup name (change, bookmark, log, ...)

                                                           *jujutsu.close()*
close()                   Close the status buffer.

                                                         *jujutsu.refresh()*
refresh()                 Refresh the status buffer (and jjsigns / lualine).

                                                        *jujutsu.annotate()*
annotate({opts?})         Open `jj file annotate` for the current buffer
                          (or opts.path) at the cursor line (or opts.line).
                          Shows a bottom panel of commits that touched the
                          file (like Diff popup `dc`).

  Options: ~
    bufnr      integer  buffer number (default: current)
    line       integer  1-based line to focus
    path       string   absolute or repo-relative path
    revision   string   starting revision for annotate
    cwd        string   workspace directory hint

                                                          *jujutsu.review()*
review({opts?})           Open a forge PR/MR review in DiffView.
                          Picks an open PR when number is omitted.

  Options: ~
    number     integer|string   PR/MR number
    cwd/root   string           workspace directory

                                                          *jujutsu.action()*
action({popup}, {action}, {args?})
                          Return a function that runs a popup action.
                          Useful for custom keymaps.
                          Example: `action("diff", "annotate")`

                                                         *jujutsu.setup()*
setup({opts})             Configure the plugin.

5. MAPPINGS                                                   *jujutsu-mappings*

Customize via `setup({ mappings = { status = {...}, popup = {...} } })`.
Set a key to |v:false| to disable it.

Popup keys (defaults): ? b c d f l m p r s u w

Status context: D E O B F P S o x  and navigation/fold keys
(`<tab>` toggles sections, working-copy file diffs, recent-commit
status, and bookmark commit history).

Log view: `<cr>` open commit, `S` open `--stat` view, `P` split popup.

Diff popup: `dd` / `dr` / `dt` side-by-side diffsplit; `dc` change history;
`da` annotate (file under cursor); `dR` review open PR/MR.

==============================================================================
6. INTEGRATIONS                                           *jujutsu-integrations*

Pickers are auto-detected. Priority: telescope, fzf-lua, mini.pick, snacks,
then the built-in finder.

Diff popup action "External viewer" uses diffview or codediff when available
(typically requires a git-colocated jj repository).

Diff popup `dd` / `dr` / `dt` open a side-by-side diffsplit tab (file list +
parent/from ↔ to) instead of a flat unified patch. `dc` opens change history
(same diffsplit, with a revision list). With a revision under the cursor it
pre-selects that change; with a file under the cursor it scopes history to that
path; otherwise repo-wide. Opening a change (`<CR>`) uses the same side-by-side
diff for that revision.

`da` opens annotate for the file under the cursor (see |jujutsu-annotate|).
`dR` opens PR/MR review (see |jujutsu-review|).

Forge: when `forge.pr_integration` is true, bookmarks may show PR numbers for
the detected provider; `o` opens the PR or commit in the browser.

Lualine: >
  require("lualine").setup({
    sections = {
      lualine_b = require("jujutsu.lualine").prepend({ "branch" }),
      lualine_x = require("jujutsu.lualine").append({
        "encoding",
        "fileformat",
        "filetype",
      }),
    },
  })
<
`components()` returns a list - use `.prepend()` / `.append()` (or
`vim.list_extend`) to flatten it into a section. Do not nest the list as a
single entry (that causes "attempt to call a table value").
Repo-wide working-copy `+`/`~`/`-` line counts (refreshed on write / cwd /
focus, not BufEnter). Rev is prefixed with a branch icon; bookmarks are the
closest ancestors of `@` (with ahead count), like oh-my-posh. Also:
`.component()`, `.rev()`, `.bookmark()`, `.diff()`, `.status()`.

7. SIGNS                                                         *jujutsu-signs*

jjsigns show working-copy line changes in the signcolumn (add / change /
delete), similar to gitsigns but display-only (no hunk navigation or reset).

Signs come from `jj diff --git` against the working-copy parents. They refresh
on BufEnter / BufWritePost / FocusGained and when `.jj` changes (filewatcher).

Disable with `disable_signs = true`. Glyphs are configured under `signs`:
>
  signs = {
    add = { text = "┃" },
    change = { text = "┃" },
    delete = { text = "▁" },
    topdelete = { text = "▔" },
    changedelete = { text = "~" },
  }
<

Highlight groups: `JujutsuSignsAdd`, `JujutsuSignsChange`, `JujutsuSignsDelete`.

==============================================================================
8. ANNOTATE                                                   *jujutsu-annotate*

Built-in `jj file annotate` (blame) UI.

Layout: annotated file on top (change id, author, date, content); bottom panel
lists commits that touched the file (same data source as Diff popup `dc`).
Selecting a commit highlights its lines and jumps to the first match.

Entry points: ~
- Diff popup `da` - file under cursor in the status buffer
- |jujutsu.annotate()| - current buffer and cursor line
- `require("jujutsu").action("diff", "annotate")`

Config: `annotate.panel_height` (default 16). File history limit comes from
`file_history.limit`.

Highlight groups: `JujutsuAnnotateHash`, `JujutsuAnnotateAuthor`,
`JujutsuAnnotateDate`, `JujutsuAnnotateCurrent`, `JujutsuAnnotateSelected`.

==============================================================================
9. PR REVIEW                                                   *jujutsu-review*

Review open pull / merge requests in the built-in DiffView with local comments,
markdown yank, and forge submit.

Providers: ~
- github     via `gh`
- gitlab     via `glab`
- forgejo    Codeberg / Forgejo via REST (`FORGEJO_TOKEN` / `CODEBERG_TOKEN`)
- bitbucket  Bitbucket Cloud via REST (`BITBUCKET_USER` + `BITBUCKET_TOKEN`)

Entry points: ~
- Diff popup `dR`
- |jujutsu.review()|

Review DiffView keys: ~
  c        comment at cursor line
  C        file comment
  v/V + c  range comment
  ;c       review-level comment
  e / i    edit unsubmitted comment at cursor
  m / M    next / previous comment
  r        toggle file reviewed (panel)
  y        yank structured markdown
  S        submit (Comment / Approve / Request changes; Draft = GitHub only)
  ?        help

Sessions are stored under `stdpath("data")/jujutsu/reviews/`.
